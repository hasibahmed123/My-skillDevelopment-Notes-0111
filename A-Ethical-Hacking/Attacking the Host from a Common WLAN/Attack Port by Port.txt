============================================================
       KALI LINUX -> WINDOWS 11
       LAN PENETRATION TESTING FIELD MANUAL
============================================================

OBJECTIVE:
--------
Assess a Windows 11 host remotely from Kali Linux.

ENVIRONMENT:
------------
Attacker : Kali Linux
Target   : Windows 11
Network  : Same Wi-Fi / LAN
Access   : Remote only
Changes  : No target configuration changes

AUTHORIZED SCOPE:
-----------------
1. Network discovery
2. TCP/UDP port scanning
3. Service enumeration
4. Vulnerability identification
5. Security configuration assessment
6. Safe authentication testing
7. Controlled proof-of-concept validation
8. Reporting and remediation

============================================================
                 PHASE 01 - RECONNAISSANCE
============================================================

[STEP 1] Identify Kali IP

    ip -br addr

[STEP 2] Identify network interface

    ip route

[STEP 3] Discover LAN devices

    sudo arp-scan --localnet

[STEP 4] Discover live hosts

    sudo nmap -sn <NETWORK-CIDR>

[STEP 5] Identify target MAC

    ip neigh show <TARGET-IP>

[STEP 6] Test connectivity

    ping -c 4 <TARGET-IP>


============================================================
              PHASE 02 - PORT DISCOVERY
============================================================

[1] ALL TCP PORTS

    sudo nmap -sS -Pn -p- --open -T3 <TARGET-IP>

[2] COMMON TCP PORTS

    sudo nmap -sS -Pn --top-ports 1000 <TARGET-IP>

[3] SERVICE VERSION DETECTION

    sudo nmap -sV -Pn <TARGET-IP>

[4] DEFAULT SAFE ENUMERATION

    sudo nmap -sC -sV -Pn <TARGET-IP>

[5] UDP DISCOVERY

    sudo nmap -sU --top-ports 100 -Pn <TARGET-IP>

[6] SAVE RESULTS

    sudo nmap -sV -sC -Pn -oA assessment <TARGET-IP>

============================================================
              PHASE 04 - SERVICE ENUMERATION
============================================================

-------------------------
A. FTP - PORT 21
-------------------------

Scan:

    nmap -sV -p21 <TARGET-IP>

Check FTP features:

    nmap -p21 --script ftp-syst <TARGET-IP>

Check anonymous access:

    nmap -p21 --script ftp-anon <TARGET-IP>

Possible findings:
    - Anonymous access
    - Cleartext authentication
    - Outdated FTP software
    - Excessive file permissions


-------------------------
B. SSH - PORT 22
-------------------------

Scan:

    nmap -sV -p22 <TARGET-IP>

Check authentication methods:

    nmap -p22 --script ssh-auth-methods <TARGET-IP>

Check host algorithms:

    nmap -p22 --script ssh2-enum-algos <TARGET-IP>

Possible findings:
    - Weak algorithms
    - Outdated SSH version
    - Password authentication exposure


-------------------------
C. TELNET - PORT 23
-------------------------

Scan:

    nmap -sV -p23 <TARGET-IP>

Check connectivity:

    nc -vz <TARGET-IP> 23

Possible findings:
    - Unencrypted credentials
    - Legacy remote administration
    - Weak authentication configuration


-------------------------
D. HTTP - PORTS 80/8080/8000
-------------------------

Scan:

    nmap -sV -p80,8000,8080 <TARGET-IP>

Check headers:

    curl -I http://<TARGET-IP>

Check HTTP methods:

    nmap -p80,8080 --script http-methods <TARGET-IP>

Check page title:

    nmap -p80,8080 --script http-title <TARGET-IP>

Check TLS:

    nmap -p443 --script ssl-cert,ssl-enum-ciphers <TARGET-IP>

Possible findings:
    - Information disclosure
    - Insecure HTTP methods
    - Outdated applications
    - Missing security headers
    - Exposed administrative interfaces


-------------------------
E. MSRPC - PORT 135
-------------------------

Scan:

    nmap -sV -p135 <TARGET-IP>

Check connectivity:

    nc -vz <TARGET-IP> 135

Possible findings:
    - Excessive RPC exposure
    - Unnecessary network services
    - Information disclosure


-------------------------
F. NETBIOS - PORT 139
-------------------------

Scan:

    nmap -sV -p139 <TARGET-IP>

Check NetBIOS information:

    nmap -p139 --script nbstat <TARGET-IP>

Possible findings:
    - Legacy protocol exposure
    - Network naming information
    - Unnecessary NetBIOS service


-------------------------
G. SMB - PORT 445
-------------------------

Scan:

    nmap -sV -p445 <TARGET-IP>

Check supported SMB protocols:

    nmap -p445 --script smb-protocols <TARGET-IP>

Check SMB security mode:

    nmap -p445 --script smb-security-mode <TARGET-IP>

Check SMB signing:

    nmap -p445 --script smb2-security-mode <TARGET-IP>

List shares with authorized credentials:

    smbclient -L //<TARGET-IP> -U <USERNAME>

Possible findings:
    - SMBv1 enabled
    - SMB signing not required
    - Excessive share permissions
    - Guest access
    - Outdated SMB implementation

If port 445 is CLOSED:
    SMB is not accepting connections on TCP 445.
    Do not assume SMB is exploitable.


-------------------------
H. RDP - PORT 3389
-------------------------

Scan:

    nmap -sV -p3389 <TARGET-IP>

Check encryption:

    nmap -p3389 --script rdp-enum-encryption <TARGET-IP>

Check connectivity:

    nc -vz <TARGET-IP> 3389

Possible findings:
    - Weak security configuration
    - Outdated RDP implementation
    - Excessive remote-access exposure


-------------------------
I. WINRM - PORTS 5985/5986
-------------------------

Scan:

    nmap -sV -p5985,5986 <TARGET-IP>

Check HTTP endpoint:

    curl -i http://<TARGET-IP>:5985/wsman

Check connectivity:

    nc -vz <TARGET-IP> 5985

Possible findings:
    - Unnecessary remote management exposure
    - Insecure transport configuration
    - Excessive management access


-------------------------
J. VNC - PORT 5900

Scan:

Check connectivity:

Possible findings:

    - Insecure VNC configuration

============================================================
             PHASE 07 - VULNERABILITY VALIDATION
============================================================

For every finding:

1. Record the service and version.
2. Identify the relevant CVE, if applicable.
3. Check the vendor's affected-version advisory.
4. Determine the required authentication.
5. Determine the actual attack prerequisites.
6. Use non-destructive validation.
7. Record evidence.
8. Recommend remediation.

Useful tools:

    nmap
    searchsploit
    Metasploit (authorized lab validation)
    Wireshark
    smbclient
    curl
    netcat
    OpenVAS / Greenbone

Search local Exploit-DB:

    searchsploit <SERVICE-NAME> <VERSION>

IMPORTANT:
---------
An Exploit-DB result does not establish that the target is vulnerable.
Verify exact versions, configuration, and prerequisites.


============================================================
             PHASE 08 - AUTHORIZED ACCESS VALIDATION
============================================================

Valid remote access requires:
    1. An exposed remote-access service.
    2. A supported authentication mechanism.
    3. Authorized credentials or an approved lab exploit.
    4. Appropriate account permissions.

SMB:
    smbclient -L //<TARGET-IP> -U <USERNAME>

SSH:
    ssh <USERNAME>@<TARGET-IP>

RDP:
    xfreerdp /v:<TARGET-IP> /u:<USERNAME>

WinRM:
    Use an approved WinRM client with authorized credentials.

These commands initiate legitimate authentication.
They do not bypass Windows security.
