======================================================================
       WINDOWS LAN PENETRATION TESTING & SECURITY ASSESSMENT
              PROFESSIONAL ENGAGEMENT PLAYBOOK
======================================================================

VERSION       : 2.0
PLATFORM      : Kali Linux → Windows 10 / Windows 11
NETWORK       : Local Area Network (LAN)
TARGET        : Personally owned / explicitly authorized Windows PC
TEST TYPE     : Black-box + Configuration-assisted Assessment
METHODOLOGY   : Reconnaissance → Enumeration → Analysis →
                Controlled Validation → Reporting → Retesting

======================================================================
01. ENGAGEMENT DEFINITION
======================================================================

OBJECTIVES:

1. Identify the Windows target and its network exposure.
2. Identify exposed TCP services.
3. Assess SMB configuration and security.
4. Evaluate authentication and authorization controls.
5. Identify security misconfigurations.
6. Assess authorized remote administration.
7. Compare locked and unlocked workstation states.
8. Examine Windows security events.
9. Document security findings and business impact.
10. Provide remediation and retesting procedures.

TESTING BOUNDARIES:

- Only the explicitly authorized Windows machine.
- Only the designated local network.
- No credential theft.
- No password cracking against real accounts.
- No persistence mechanisms.
- No malware deployment.
- No destructive exploitation.
- No unauthorized access to personal information.
- No firewall or antivirus disabling.

04. PHASE 1 - NETWORK RECONNAISSANCE
======================================================================

OBJECTIVE:

Understand the local network before interacting with the target.

STEP 1 - IDENTIFY NETWORK INTERFACES:

    ip addr

STEP 2 - IDENTIFY DEFAULT GATEWAY:

    ip route

STEP 3 - IDENTIFY TARGET ROUTE:

    ip route get <TARGET_IP>

STEP 4 - IDENTIFY NETWORK NEIGHBORS:

    ip neigh

STEP 5 - IDENTIFY DEVICES ON LOCAL NETWORK:

    sudo arp-scan --localnet

DOCUMENT:

    Attacker IP:
    Target IP:
    Target MAC:
    Gateway:
    Subnet:
    Interface:

EXPECTED OUTPUT:

    A confirmed target IP and network interface.

PROFESSIONAL NOTE:

Do not assume an IP address belongs to the target based
only on its presence in the ARP table.

Correlate the MAC address with the Windows machine.

======================================================================
05. PHASE 2 - HOST DISCOVERY
======================================================================

OBJECTIVE:

Establish whether the target is reachable.

STEP 1 - BASIC CONNECTIVITY:

    ping -c 4 <TARGET_IP>

STEP 2 - TCP HOST DISCOVERY:

    sudo nmap -sn <TARGET_IP>

STEP 3 - RECORD NETWORK OBSERVATIONS:

    - Host availability
    - Response behavior
    - MAC address
    - Network reachability

IMPORTANT:

ICMP may be blocked by Windows Firewall.

A failed ping does not prove that the target is offline.

Use TCP-based verification where appropriate.

======================================================================
06. PHASE 3 - PORT & SERVICE ENUMERATION
======================================================================

OBJECTIVE:

Identify exposed services and determine their configurations.

STEP 1 - COMMON WINDOWS SERVICES:

    nmap -Pn -sV --version-light \
    -p 135,139,445,3389 <TARGET_IP>

PORT REFERENCE:

    135  = Microsoft RPC Endpoint Mapper
    139  = NetBIOS Session Service
    445  = SMB over TCP
    3389 = Remote Desktop Protocol

STEP 2 - FULL TCP PORT DISCOVERY:

    sudo nmap -Pn -p- -T3 <TARGET_IP>

STEP 3 - SERVICE IDENTIFICATION:

    sudo nmap -Pn -sV -p <OPEN_PORTS> <TARGET_IP>

STEP 4 - SAVE SCAN RESULTS:

    sudo nmap -Pn -sV \
    -p 135,139,445,3389 \
    -oA windows_service_assessment <TARGET_IP>

DOCUMENT:

    Open Ports:
    Closed Ports:
    Filtered Ports:
    Detected Services:
    Service Versions:
    Unexpected Services:

PROFESSIONAL NOTE:

An open port is an exposed service, not automatically
a vulnerability.

Identify the service, configuration and security impact
before assigning a risk rating.

======================================================================
07. PHASE 4 - SMB SECURITY ASSESSMENT
======================================================================

OBJECTIVE:

Assess SMB protocol configuration and network exposure.

STEP 1 - SMB PROTOCOL DISCOVERY:

    nmap -Pn -p 445 --script smb-protocols <TARGET_IP>

STEP 2 - SMB SIGNING ASSESSMENT:

    nmap -Pn -p 445 \
    --script smb2-security-mode <TARGET_IP>

STEP 3 - SMB HOST INFORMATION:

    nmap -Pn -p 445 \
    --script smb-os-discovery <TARGET_IP>

STEP 4 - ANONYMOUS SHARE ENUMERATION:

    smbclient -L //<TARGET_IP>/ -N

STEP 5 - AUTHORIZED SHARE ENUMERATION:

    nxc smb <TARGET_IP> \
    -u '<LAB_USERNAME>' \
    -p '<LAB_PASSWORD>' \
    --shares --local-auth

Use dedicated lab credentials.
Avoid placing real passwords in shell history.

DOCUMENT:

    SMB Port:
    SMB Protocols:
    SMBv1 Availability:
    SMB Signing:
    Anonymous Enumeration:
    Authenticated Enumeration:
    Available Shares:
    Share Permissions:

SECURITY CONSIDERATIONS:

    - SMBv1 should generally be disabled.
    - SMB signing should be configured appropriately.
    - Anonymous access should be restricted.
    - Share permissions should follow least privilege.
    - TCP 445 should not be unnecessarily exposed.

IMPORTANT:

SMB signing not being required is a configuration finding.
It is not proof that an SMB relay attack is possible.

======================================================================
08. PHASE 5 - AUTHENTICATION & AUTHORIZATION
======================================================================

OBJECTIVE:

Determine which resources are accessible using
authorized test credentials.

STEP 1 - AUTHENTICATED ENUMERATION:

    nxc smb <TARGET_IP> \
    -u '<LAB_USERNAME>' \
    -p '<LAB_PASSWORD>' \
    --shares --local-auth

STEP 2 - TEST AUTHORIZED SHARE ACCESS:

    smbclient //<TARGET_IP>/<SHARE_NAME> \
    -U '<LAB_USERNAME>'

STEP 3 - INSPECT ACCESS:

    smb: \> ls

STEP 4 - DOCUMENT PERMISSIONS:

    - Share listing
    - Read access
    - Write access
    - Access denied
    - Administrative restrictions

ASSESSMENT QUESTIONS:

    1. Can anonymous users enumerate shares?
    2. Can standard users access restricted shares?
    3. Are sensitive directories unnecessarily exposed?
    4. Are write permissions excessively broad?
    5. Are administrative shares appropriately restricted?

IMPORTANT:

Successful authentication does not necessarily mean
administrator access.

Authentication and authorization must be evaluated separately.

======================================================================
09. PHASE 6 - LOCKED VS UNLOCKED COMPARISON
======================================================================

OBJECTIVE:

Determine whether workstation state changes network exposure.

STATE A:

    Windows powered on.
    Windows at lock screen.
    Wi-Fi connected.
    Target awake.

RUN:

    ping -c 4 <TARGET_IP>

    nmap -Pn -sV \
    -p 135,139,445,3389 <TARGET_IP>

    nmap -Pn -p 445 \
    --script smb-protocols <TARGET_IP>

    nmap -Pn -p 445 \
    --script smb2-security-mode <TARGET_IP>

    smbclient -L //<TARGET_IP>/ -N

STATE B:

    Windows unlocked.
    User logged in.
    Wi-Fi connected.
    Target awake.

REPEAT THE SAME COMMANDS.

COMPARE:

    - Host reachability
    - TCP port availability
    - Service identification
    - SMB protocol configuration
    - Anonymous access
    - Authenticated access
    - Share accessibility

PROFESSIONAL INTERPRETATION:

If both states expose identical services:

    The lock screen did not materially change
    the observed network exposure.

If results differ:

    Investigate service configuration, Windows Firewall
    profiles, application state and network policy.

Do not assume that unlocking Windows exposes credentials
or grants remote administrative access.

10. PHASE 7 - CONTROLLED REMOTE ADMINISTRATION VALIDATION
======================================================================

OBJECTIVE:

Determine whether explicitly authorized remote
administration is configured.

REQUIREMENTS:

    - Dedicated lab administrator account.
    - Explicit authorization.
    - Appropriate Windows configuration.
    - Non-destructive validation.

STEP 1 - VERIFY AUTHENTICATION:

    nxc smb <TARGET_IP> \
    -u '<LAB_ADMIN>' \
    -p '<LAB_PASSWORD>' \
    --local-auth

STEP 2 - VERIFY ADMINISTRATIVE ACCESS:

    Use an approved administrative management channel
    to verify the effective Windows identity.

STEP 3 - DOCUMENT:

    - Authentication result
    - Account privileges
    - Remote administration configuration
    - Firewall restrictions
    - Access control
    - Audit records

OPTIONAL CONTROLLED VALIDATION:

Where authorized remote execution is already configured,
a harmless identity check can validate the execution context:

    nxc smb <TARGET_IP> \
    -u '<LAB_ADMIN>' \
    -p '<LAB_PASSWORD>' \
    --local-auth -x "whoami"

This is an administrative validation test, not a
Windows lock-screen bypass.

DO NOT:

    - Attempt unauthorized privilege escalation.
    - Execute destructive commands.
    - Disable security controls.
    - Establish persistence.
    - Modify unrelated user data.

11. PHASE 8 - WINDOWS CONFIGURATION REVIEW
======================================================================

OBJECTIVE:

Inspect the target's security configuration.

RUN ON WINDOWS POWERSHELL:

STEP 1 - WINDOWS INFORMATION:

    Get-ComputerInfo

STEP 2 - WINDOWS FIREWALL STATUS:

    Get-NetFirewallProfile |
    Select-Object Name, Enabled, DefaultInboundAction

STEP 3 - SMB SERVER CONFIGURATION:

    Get-SmbServerConfiguration

STEP 4 - SMB SHARES:

    Get-SmbShare

STEP 5 - SMB SESSIONS:

    Get-SmbSession

STEP 6 - SMB SHARE ACCESS:

    Get-SmbShareAccess

STEP 7 - LOCAL USERS:

    Get-LocalUser

STEP 8 - LOCAL ADMINISTRATORS:

    Get-LocalGroupMember -Group "Administrators"

DOCUMENT:

    Firewall Profiles:
    SMB Configuration:
    SMB Shares:
    Share Permissions:
    Local Accounts:
    Administrator Membership:

SECURITY REVIEW:

    - Excessive privileges
    - Unnecessary accounts
    - Unnecessary shares
    - Weak inbound firewall restrictions
    - Insecure SMB configuration
    - Unnecessary remote administration

12. PHASE 9 - VULNERABILITY ANALYSIS
======================================================================

OBJECTIVE:

Identify security weaknesses based on collected evidence.

ASSESS THE FOLLOWING:

    A. SMB SECURITY

       - SMBv1 enabled
       - SMB signing configuration
       - Anonymous access
       - Excessive share permissions
       - Unnecessary network exposure

    B. WINDOWS CONFIGURATION

       - Missing security updates
       - Weak firewall configuration
       - Excessive local privileges
       - Unnecessary services
       - Insecure remote administration

    C. AUTHENTICATION

       - Weak authentication policies
       - Excessive account privileges
       - Unnecessary remote logon rights
       - Inadequate account protection

    D. NETWORK EXPOSURE

       - Unnecessary open ports
       - Exposed administrative services
       - Inadequate network segmentation
       - Unrestricted access to sensitive services

VULNERABILITY VALIDATION:

For each suspected weakness:

    1. Identify the affected component.
    2. Verify the configuration or software version.
    3. Identify the applicable security advisory.
    4. Determine whether the weakness is applicable.
    5. Validate safely using a non-destructive method.
    6. Record supporting evidence.
    7. Determine the actual security impact.

IMPORTANT:

Do not classify a system as vulnerable based solely
on an exposed port or an outdated-looking banner.

Verify the finding.

13. PHASE 10 - NETWORK TRAFFIC ANALYSIS
======================================================================

OBJECTIVE:

Observe traffic generated during authorized testing.

STEP 1 - IDENTIFY INTERFACES:

    ip link

STEP 2 - CAPTURE SMB TRAFFIC:

    sudo tcpdump -i <INTERFACE> \
    -nn host <TARGET_IP> and port 445

STEP 3 - SAVE PCAP:

    sudo tcpdump -i <INTERFACE> \
    -nn host <TARGET_IP> and port 445 \
    -w windows_smb_assessment.pcap

STEP 4 - READ CAPTURE:

    tshark -r windows_smb_assessment.pcap

STEP 5 - INSPECT USING WIRESHARK:

    Open the saved PCAP file.

USEFUL DISPLAY FILTERS:

    smb2
    tcp.port == 445
    ip.addr == <TARGET_IP>

INVESTIGATE:

    - SMB negotiation
    - Connection attempts
    - Authentication exchanges
    - Share access requests
    - Connection failures
    - Unexpected traffic

IMPORTANT:

Use traffic captures only for authorized lab traffic.
Do not collect unrelated users' communications.

14. PHASE 11 - WINDOWS EVENT LOG ANALYSIS
======================================================================

OBJECTIVE:

Correlate Kali testing activity with Windows security logs.

RUN ON WINDOWS POWERSHELL:

STEP 1 - RECENT SECURITY EVENTS:

    Get-WinEvent -LogName Security -MaxEvents 100

STEP 2 - FAILED LOGONS:

    Get-WinEvent -FilterHashtable @{
        LogName='Security'
        Id=4625
    } -MaxEvents 30

STEP 3 - SUCCESSFUL LOGONS:

    Get-WinEvent -FilterHashtable @{
        LogName='Security'
        Id=4624
    } -MaxEvents 30

IMPORTANT EVENT IDS:

    4624 = Successful logon
    4625 = Failed logon
    4672 = Special privileges assigned
    5140 = Network share accessed
    5145 = Network share access checked

DOCUMENT:

    - Event ID
    - Timestamp
    - Account name
    - Source IP
    - Logon type
    - Accessed resource
    - Authentication result

IMPORTANT:

Relevant audit policies must be enabled.

An event may not exist if the corresponding audit
subcategory is not configured.

15. PHASE 12 - RISK ASSESSMENT
======================================================================

OBJECTIVE:

Determine the severity and practical impact of findings.

RISK CLASSIFICATION:

    CRITICAL:
        Severe compromise with major security impact.

    HIGH:
        Significant unauthorized access or compromise risk.

    MEDIUM:
        Meaningful weakness requiring corrective action.

    LOW:
        Limited impact or restricted exposure.

    INFORMATIONAL:
        Observation without demonstrated security impact.

USE CVSS 4.0 WHERE APPLICABLE.

For each finding, document:

    Finding ID:
    Finding Title:
    Affected Component:
    Severity:
    CVSS Score:
    Evidence:
    Technical Explanation:
    Security Impact:
    Exploitability:
    Remediation:
    Retest Status:

Do not assign severity based solely on the
number of open ports.

======================================================================
16. PHASE 13 - SECURITY REMEDIATION
======================================================================

RECOMMENDATIONS:

NETWORK:

    - Restrict unnecessary inbound connections.
    - Limit TCP 445 to trusted devices.
    - Apply network segmentation.
    - Avoid exposing SMB to untrusted networks.

SMB:

    - Disable SMBv1 where unnecessary.
    - Configure SMB signing appropriately.
    - Restrict anonymous access.
    - Apply least-privilege share permissions.
    - Review administrative shares.

WINDOWS:

    - Install security updates.
    - Enable Windows Firewall.
    - Review local administrator membership.
    - Remove unnecessary accounts.
    - Restrict remote administration.
    - Maintain endpoint protection.

AUTHENTICATION:

    - Use strong unique passwords.
    - Apply appropriate account policies.
    - Restrict unnecessary remote logons.
    - Protect administrative credentials.

MONITORING:

    - Enable relevant audit policies.
    - Review failed logons.
    - Monitor unexpected share access.
    - Investigate suspicious authentication activity.

20. PROFESSIONAL COMPLETION CRITERIA
======================================================================

An assessment is not complete simply because Nmap
has finished scanning.

A professional assessment must demonstrate:

    1. WHAT is exposed?
    2. WHY is it exposed?
    3. IS the exposure actually vulnerable?
    4. CAN the security weakness be safely validated?
    5. WHAT is the realistic security impact?
    6. WHAT evidence supports the finding?
    7. HOW should the weakness be corrected?
    8. HAS the correction been verified?

FINAL DELIVERABLES:

    - Network assessment results
    - Nmap output files
    - SMB configuration evidence
    - Authorized access validation results
    - Traffic capture where relevant
    - Windows event log evidence
    - Vulnerability register
    - Risk assessment
    - Remediation recommendations
    - Retest report
